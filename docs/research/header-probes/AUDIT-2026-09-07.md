## Confirmed coverage

1,073-entry dictionary, it totals 1,155 distinct names. It also accepts headers

## Five reviews and fixes

1. **Effective coverage and values.** The second variants ended up after more than
   a thousand generic names. Now every known recipe alternates its variants before
   untyped discovery. 23 recipes and 11 typed names were added, nine of them also
   new to the union. Tests: `documentedVariantsPrecedeUntypedDiscovery`
   and `typedTraceRecipesHaveValidTraceIds`.
2. **Response parsing.** gzip/deflate chains are decoded in reverse order,
   with up to three layers and 512 KiB per layer. An invalid charset or malformed
   bytes leave the body unevaluated. A parameter containing `json` no longer turns a
   binary MIME into text. Tests for UTF-16LE with double gzip, invalid UTF-8, binary
   MIME, truncated compression and size limits.
3. **Causality.** A dynamic body hid stable header changes. Now status/headers can
   be confirmed with all four controls even when the body is dynamic.
   Incomplete bodies still do not constitute differences on their own. The tests for
   control contamination, request-only markers, errors and WAF are kept.
4. **Cost and eligibility.** Uppercase and default ports shared a server but not a
   budget. They now share a per-origin quota. Percent-encoded action paths and invalid
   authorities are checked. The single queue/worker, quota, interval, cancellation and
   pause-on-errors are kept. Test `equivalentOriginSpellingsShareBudget`.
5. **Context and publishing.** Custom values are preserved when deduplicating contexts,
   ordering across distinct names is normalized and the order of duplicates is preserved.
   Native URLs no longer turn `%2F` into `%252F`. Tests `HeaderInfluenceContextTest`
   and `nativeProbeIdentityDoesNotDoubleEncodePathOrQuery`. The six exchanges,
   the clean retest template and the marker exclusion in handler/passive scanner were reviewed.

## Validation and limits

Final build: `clean test shadowJar`, with Java 21 and the Apache fixture enabled.
Result: **183 tests, zero failures, errors or skips**. The three Quimera JARs
(build/libs, project root and Desktop) were regenerated and verified with SHA-256
`44b7d0f5fb9c58175a05787c03ba62192195b914e3004e99517175fd0fa3b04f`.
The packaged archive contains all 216 recipes and passed the ZIP integrity check.

The suite includes real HTTP against a local Java server. The engine was also run
against a local Apache with `mod_headers`, which reflects `X-Display` in `X-Audit-Echo`;
the engine confirmed the header sink via controls and two canaries. The optional test
`realApacheModHeadersConfirmsResponseHeaderReflection` is enabled with
`QUIMERA_APACHE_FIXTURE_URL=http://127.0.0.1:PORT/index.html`.
The essential configuration of that fixture is:

```apache
Header set X-Audit-Echo "expr=%{req:X-Display}"
```

This is not equivalent to a runtime test against every CMS nor to a visual session in Burp.
Brotli/Zstandard and overly large bodies are still not compared; headers are.
Not all value combinations nor dependencies between several headers are tested.
The budget may produce partial coverage. Authentication, framing and method-changing
headers remain outside this module's mutations. The absence of findings does not
certify the absence of influence or XSS.
